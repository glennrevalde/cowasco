# Additional module for the Water + Coop systems (v2): requirements checklist

This maps every request of the workbook `ADDITIONAL_MODULE_FOR_WATER_COOP_SYSTEMS_v2.xlsx` (Sheet1: 23 screenshots
with notes) to the code that implements it and the test that exercised it. Status: **Done** means built, reachable
from the menu, and run in the tests or by hand on the sample database.

The database change is one upgrade script, `database/migrations/2026_12_20_member_lists_class_je_changes.sql`
(MySQL 5.5, safe to run twice). New installations get the same through `database/schema.sql`, the water-billing
migration and `tools/install.php`.

## 2. Decisions

| # | Decision | Reason |
|---|---|---|
| A1 | The class is required, never guessed. A form with no class set up says where to add them (Chart of Accounts > Class List). Records saved before the upgrade keep an empty class. | "cannot proceed saving the transaction if no class is selected". |
| A2 | The class box starts on the class the user chose last (per session). | A teller of one office chooses it once. |
| A3 | A correction (bill edit, debit / credit, reversal, refund, status change) asks for its own class, starting on the bill's class. | The correcting entry is a transaction of its own. |
| A4 | Recurring bills take the class chosen on Generate Due Bills (or on the enrolment that makes catch-up bills). The command-line runner takes `--class=CLASS_ID`; without it the bills take the water branch's class as before. | A scheduled run has nobody to choose. |
| A5 | A journal entry change is applied only by a second user with the Approve right on Make Journal Entries; it is applied through the same save as a new entry (closing date, balance check, audit trail with the explanation as the reason). | Maker-checker; no silent edit of the books. |
| A6 | Every member is a customer of the cooperative: the customer record is the member's party's own customer role, made when the member is saved (and, for members saved before the upgrade, when a customer list is first opened, 400 at a time). | So members appear on Customer:Job and the POS without a second record per person. |

## 3. Upgrade

Back up the database, copy the files over the installation and run
`database/migrations/2026_12_20_member_lists_class_je_changes.sql` (phpMyAdmin Import, Navicat Execute SQL File, or
`php tools/upgrade.php`). Then, before the first transaction, make sure Chart of Accounts > Class List holds the
classes (for example one per branch, and one for the water utility): the forms above are not saved without one.
