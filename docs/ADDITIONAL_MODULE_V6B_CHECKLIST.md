code that implements it and the test that exercised it. Its only sheet, **Sheet3**, holds six screenshots with notes
(rows 3 to 173). Status: **Done** means built, reachable from the menu, and run in the tests and in a browser on the
sample database.

Version 35 adds no migration and changes no table: nothing to run on the database (`UPGRADE_v35.txt`).

## 2. Decisions

| # | Decision | Reason |
|---|---|---|
| D1 | A delete removes the application and what belongs only to it; a released application (or one whose voided release is on record) cannot be deleted. The audit trail keeps the application as it was. | A released loan's application is part of its record; the audit trail keeps what was deleted. |
| D2 | The pages of a run print one at a time, each on its own press after the first: the passbook must be turned by hand between pages. The lines are marked printed only on the teller's confirmation, for all the pages or the first ones. | A passbook printer prints the page that is in it; the two-step printing of version 34 (print, then confirm) is kept so a jam is printed again. |
| D3 | The form of Savings Account Transaction is cleared after the last printing of the transaction (the passbook confirmed, or the validation when no passbook printing follows). Loan Collection keeps the member and the loan after the passbook (a member may have other loans to print). | The note of the workbook is on Savings Account Transaction. |
| D4 | The allocation order of the dues stays a policy (Cooperative Profile & Policies, default penalty, interest, principal); what is left after the dues always goes to the principal. | The workbook's priority is the default order; a cooperative that set another order keeps it. |
| D5 | Payments saved before version 35 keep their split; nothing is recomputed. | A posted payment is in the books and on the receipt. |
