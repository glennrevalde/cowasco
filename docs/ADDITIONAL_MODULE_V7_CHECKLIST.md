# Additional module for the Water + Coop systems (v7): requirements checklist

This maps every request of `ADDITIONAL_MODULE_FOR_WATER_COOP_SYSTEMS_v7.xlsx` (version 36) to the code that implements
it and the test that exercised it. The workbook has three sheets; **Sheet1** holds two screenshots with notes in column P
(Sheet2 and Sheet3 are empty):

- image 1 (A2:O35): **Edit account 1009** (Cash on Hand - Accounting Office), with the **Account type** drop-down marked
  (D13:O19); notes P19, P20, P21;
- image 2 (A40:O74): the **Chart of Accounts**, where 1000 Cash shows 0.00 while its sub-accounts have balances (marked
  at L52:O53 and M56:O61); notes P53, P56, P57.

Status: **Done** means built, reachable from the menu, and run in the tests and in a browser on the sample database and on
a copy of a migrated real chart of accounts.

Version 36 adds one migration, `database/migrations/2027_01_24_account_types.sql` (`UPGRADE_v36.txt`).

## 2. Decisions

| # | Decision | Reason |
|---|---|---|
| D1 | A type of the user's **behaves as** one built-in type; `accounts.account_type` keeps that built-in type and `accounts.type_id` holds the chosen type. | Banking, receivables, payables, the teller, the POS and the posting rules all choose accounts by the built-in type. Keeping it means no module changes behaviour and no posted amount moves; the new type only names, places and links the account. |
| D2 | A sub-account is shown under its main account and takes the classification of the main account's type, whatever its own type. | The workbook's 1000 Cash and its sub-accounts are one classification; the main account's total must be on one line of the summary. |
| D3 | The cash flow section is set on the type (not on each account). The built-in types keep their usual sections; Bank is cash and cash equivalents. | One place to set it, the same for every account of a classification, so the statement ties to the cash accounts by construction. |
| D4 | Accumulated depreciation (a Fixed Asset account with a Credit normal balance, in investing) stays an operating adjustment. | It is a non-cash charge; as in version 35. |
| D5 | Accounts the modules post to (system accounts) can take only a type of their own built-in type; an account with entries, a main account with sub-accounts and a sub-account keep their category. | The modules rely on them; a change of category would move posted amounts between statements. |
| D6 | A type heading is left out where a group of the statement holds only one built-in type and none of the user's (Fixed Assets, Equity, the income statement sections). | The group heading already names it; repeating it would add a heading and a total line with nothing new. |
| D7 | The sample database gets the two types of the workbook (Cash: 1000 with its sub-accounts and 1009; Loans Receivable: 1210 to 1215). A new installation and an upgraded database start with the built-in types only. | The sample shows the feature; a live chart is classified by its owner. |

Run `database/migrations/2027_01_24_account_types.sql` (or `php tools/upgrade.php`), copy the files and press Ctrl+F5
once. See `UPGRADE_v36.txt` for the set-up of the Cash and Loans Receivable types.
