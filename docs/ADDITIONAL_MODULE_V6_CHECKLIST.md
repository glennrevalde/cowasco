# Additional module for the Water + Coop systems (v6): requirements checklist

This maps every request of the workbook `ADDITIONAL_MODULE_FOR_WATER_COOP_SYSTEMS_v6.xlsx` to the code that implements
it and the test that exercised it. **Sheet2** holds the requests: eight pictures with notes (rows 1 to 236). **Sheet3**
holds one screenshot (Loans > Restructure / Renew / Write Off, loan 01-6-0000002) without a note. Status: **Done** means
built, reachable from the menu, and run in the tests or by hand on the sample database.

The database change is one upgrade script, `database/migrations/2027_01_17_passbook_designer.sql` (MySQL 5.5, safe to
run twice). New installations get the same through `database/schema.sql` and `tools/install.php`.

## 3. Decisions

| # | Decision | Reason |
|---|---|---|
| D1 | Capacity to pay is carried from the member's last application (the one saved last), whatever its status; the application keeps its own entries. The eligibility check of the net disposable income still reads the member's Financial Information tab. | "These data will become the initial data on the next loan"; the eligibility rule is the cooperative's policy and was not asked to change. |
| D2 | A credit investigation carries the facts (residence, addresses, children, income, assets, references, informants), not the findings, score or recommendation, which are shown in the note. | The findings of one investigation are not those of the next; the investigator sees them. |
| D3 | The design is saved as one design per passbook type (layout_json). A type saved before keeps its settings (columns, header, cover, footer text) until it is saved on Passbook Types, and prints as before. | The upgrade changes no printing by itself; the user checks and saves each type. |
| D4 | Start Line Skip / No. of Line Skip / Max Lines take their meaning in the former program; a type that listed its fold lines is converted by the migration. The installed Loan Passbook, if never changed, takes the former program's loan set-up. | The workbook's set-up (13, 2, 29) and its rules. |
| D5 | The header prints on a new page before line 1 (or with every printing, or never, per type); "Print the header" prints it alone. | "the system will reset printing to line 1, after printing the passbook header". |
| D6 | The loan passbook prints the release, the payments, the error corrections, the payoff by a new loan and the recoveries; not the charges (penalties, adjustments, waivers, accruals). | The lines of the former loan passbook; the Loan Ledger Form's passbook view (version 33) shows the same. |
| D7 | Condensed print is a characters-per-inch setting (the characters narrowed by the browser), not a different font. | A browser cannot send printer control codes; the narrowing gives the same width on the paper. |

## 4. Upgrade

Back up the database, copy the files over the installation and run `database/migrations/2027_01_17_passbook_designer.sql`
(phpMyAdmin Import, Navicat Execute SQL File, or `php tools/upgrade.php`). Then follow `UPGRADE_v34.txt`: check and save
each passbook type, print a test page, and check the passbook type of each product.
