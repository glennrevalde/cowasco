# Additional module for the Water + Coop systems (v3): requirements checklist

This maps every request of the workbook `ADDITIONAL_MODULE_FOR_WATER_COOP_SYSTEMS_v3.xlsx` (Sheet2: 25 screenshots
with notes) to the code that implements it and the test that exercised it. Status: **Done** means built, reachable
from the menu, and run in the tests or by hand on the sample database.

The database change is one upgrade script, `database/migrations/2026_12_27_member_defaults_savings_center.sql`
(MySQL 5.5, safe to run twice). New installations get the same through `database/schema.sql`, the water-billing
migration and `tools/install.php`.

## 2. Decisions

| # | Decision | Reason |
|---|---|---|
| B1 | An error correction is a transaction of its own with the error-correct code, stored negative in the column of the transaction it negates; the erroneous transaction stays and is marked corrected. A transaction already in the passbook is never deleted. | The passbook keeps both lines, as in the former program. |
| B2 | Delete is a void with the reason: the teller's own transaction of the day at once, anything else with a supervisor. | Maker-checker on corrections of other people's work. |
| B3 | A back entry follows the policy "Days a transaction may be back-dated" or the permission to record back-dated member transactions. | The same rule as every member transaction. |
| B4 | The members' customer and supplier records stay in the books as the records of the role the member plays; the name pickers and reports show the member once. | The receivable and payable sub-ledgers keep working (A/R needs a customer, A/P a supplier) while the user sees one name. |
| B5 | Savings and loan items are no longer taken on the official receipt; receipts posted before stay as they are. | "those transactions should be transacted in their corresponding modules". |
| B6 | The sample passbook type prints the line number and the account name and number on every page; passbook types of an existing database are not changed by the upgrade. | Positions depend on the passbook stock of each cooperative; UPGRADE_v31.txt says what to set. |

## 3. Upgrade

Back up the database, copy the files over the installation and run
`database/migrations/2026_12_27_member_defaults_savings_center.sql` (phpMyAdmin Import, Navicat Execute SQL File, or
`php tools/upgrade.php`). Then follow `UPGRADE_v31.txt`: the tellers' cash accounts, the transaction codes, and the
passbook positions.
